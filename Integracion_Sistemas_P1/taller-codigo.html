🛠️ Taller: cómo construir el código paso a paso

El taller se resuelve con 3 archivos de texto. No necesitas programar un backend. Aquí tienes el camino completo y los archivos reales (basados en la Orders API del PDF) para copiar, descargar y adaptar a tu dominio.

🧭 Orden recomendado: carpeta → openapi.yaml → validar → Postman → README → (opcional) mock o backend

1 Qué vas a construir

Semana3_API_REST/
├── openapi.yaml            ← el contrato (lo más importante)
├── README.md               ← explica y justifica tu diseño
└── postman/

4 Paso 1 · Escribir el openapi.yaml en 6 bloques

No lo escribas de arriba abajo de un tirón. Ve por bloques y valida cada tanto. Abre cada bloque:

🧱 Bloque 1 · Cabecera: openapi, info, servers

Dice qué es tu API, su versión y dónde vive. Son datos obligatorios del taller.

openapi: 3.0.3
info:
  title: Orders API
  version: 1.0.0
  description: API para la gestión de pedidos
servers:
  - url: http://localhost:8080
paths:
components:
  schemas:
🧬 Bloque 2 · Modelos reutilizables en components/schemas

Declara los datos una sola vez: lo que envías (CreateOrderRequest), lo que recibes (Order) y el error (Error). Después los reutilizas con $ref.

components:
  schemas:
    CreateOrderRequest:
      type: object
      required: [customerId, items]
      properties:
        customerId:
          type: string
        items:
          type: array
          items:
            $ref: '#/components/schemas/OrderItem'
    Error:
      type: object
      required: [code, message]
      properties:
        code:
          type: string
        message:
          type: string
        correlationId:
          type: string
➕ Bloque 3 · POST /orders (request body + éxito + 2 errores)

Una operación completa: qué envías (requestBody), qué pasa si sale bien (201) y los errores (400, 422).

paths:
  /orders:
    post:
      summary: Crear un pedido
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/CreateOrderRequest'
            example:
              customerId: C-1024
              items:
                - productId: P-500
                  quantity: 2
      responses:
        '201':
          description: Pedido creado
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Order'
        '422':
          description: Regla de negocio incumplida
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Error'
🔍 Bloque 4 · GET /orders/{orderId} (path parameter)

El nombre entre llaves de la ruta debe coincidir con el name del parámetro, y in: path siempre es required: true.

  /orders/{orderId}:
    get:
      summary: Consultar un pedido
      parameters:
        - name: orderId
          in: path
          required: true
          schema:
            type: string
      responses:
        '200':
          description: Pedido encontrado
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Order'
        '404':
          description: Pedido inexistente
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Error'
🔎 Bloque 5 · GET /orders?customerId= (query parameter)

El filtro va en in: query y normalmente es opcional. Va dentro de /orders, junto a post.

    get:
      summary: Buscar pedidos
      parameters:
        - name: customerId
          in: query
          required: false
          schema:
            type: string
      responses:
        '200':
          description: Lista de pedidos
          content:
            application/json:
              schema:
                type: array
                items:
                  $ref: '#/components/schemas/Order'
♻️ Bloque 6 · PATCH y respuestas reutilizables

Si varias operaciones devuelven el mismo error, defínelo una vez en components/responses y reutilízalo. Así no duplicas nada.

components:
  responses:
    NotFound:
      description: El recurso solicitado no existe
      content:
        application/json:
          schema:
            $ref: '#/components/schemas/Error'
          example:
            code: ORDER_NOT_FOUND
            message: Order O-0000 was not found
            correlationId: 9be1a7c4-5521-4f0a
# luego, en cualquier operación:
#   '404':
#     $ref: '#/components/responses/NotFound'

8 Paso 3 · Probar el contrato sin escribir backend

Opción A · Mock con Prism Complemento

Levanta un servidor falso que responde con los example de tu contrato.

npx @stoplight/prism-cli mock openapi.yaml

Por defecto queda en http://127.0.0.1:4010. En Postman cambia baseUrl a esa dirección.

Opción B · Backend de ejemplo Complemento

Un servidor Express de ~100 líneas que cumple el contrato (carpeta extras_opcionales/server).

cd extras_opcionales/server npm install node server.js

Queda en http://localhost:8080, igual que tu servers.

Con el backend de ejemplo puedes comprobar cada código de respuesta:

PruebaEsperado
POST /orders con datos válidos201
POST /orders con quantity 9999422 PRODUCT_NOT_AVAILABLE
POST /orders sin customerId400 INVALID_REQUEST
GET /orders/O-9831200
GET /orders/O-0000404 ORDER_NOT_FOUND
PATCH dos veces a CANCELLED200 y luego 409
curl -i -X POST http://localhost:8080/orders -H 'Content-Type: application/json' \ -d '{"customerId":"C-1024","items":[{"productId":"P-500","quantity":2}]}'
🔎 ¿Qué hace cada parte del server.js?
  • Rutas: una función por operación del contrato (POST, GET, GET por id, PATCH).
  • Validación: revisa tipos y campos requeridos y responde 400 con el modelo de error.
  • Reglas de negocio: sin stock responde 422; pedido cancelado responde 409.
  • Errores: siempre {code, message, correlationId}; el detalle interno nunca sale al cliente.
  • Seguridad básica: límite de tamaño del body, rate limiting simple y token Bearer opcional (ver Seguridad de APIs).

9 Paso 4 · Postman, clic por clic

1️⃣ Import→2️⃣ Elegir openapi.yaml→3️⃣ Importar como colección→4️⃣ Variable baseUrl→5️⃣ Send→6️⃣ Exportar a postman/
  1. En Postman pulsa Import y arrastra tu openapi.yaml.
  2. Elige generar una colección (la pantalla puede variar según la versión de Postman).
  3. Comprueba que aparecen las 4 operaciones con sus métodos, parámetros y body.
  4. Crea o revisa la variable baseUrl (por ejemplo http://localhost:8080).
  5. Prepara al menos 3 requests: POST /orders, GET /orders/{orderId} y GET /orders?customerId=C-1024.
  6. Exporta la colección (formato v2.1) y guárdala en postman/API.postman_collection.json.

Opcional Complemento: en la pestaña Tests de cada request puedes automatizar comprobaciones:

pm.test("Status 201 Created", () => pm.response.to.have.status(201));
pm.test("Devuelve id y status", () => {
  const json = pm.response.json();
  pm.expect(json).to.have.property("id");
  pm.expect(json.status).to.eql("CREATED");
});
pm.collectionVariables.set("orderId", pm.response.json().id);
