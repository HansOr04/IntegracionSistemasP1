Cheat sheet (una página)

Evolución

  • Batch → EAI → SOA/ESB → APIs/REST → Microservicios → EDA
  • Cada paso baja un acoplamiento y trae un nuevo costo
  • Conviven: no se reemplazan de golpe

Acoplamiento y cohesión

  • Meta: bajo acoplamiento, alta cohesión
  • Tipos: plataforma, temporal, ubicación, datos, semántico

Batch / EAI / SOA / ESB

  • Batch: bloque programado, latencia alta
  • EAI: hub-and-spoke; hub = punto único de fallo
  • SOA: servicios con contrato (WSDL)
  • ESB: enruta, transforma, media protocolos

Microservicios y EDA

  • MS: autónomos, BD propia, despliegue independiente
  • EDA: evento = hecho pasado; productor no conoce consumidores
  • Costo: consistencia eventual, idempotencia

Los 4 estilos EIP

  • File Transfer: simple, latencia alta, legacy
  • Shared DB: consistente, acoplado al esquema
  • RPC: síncrono, acoplamiento temporal
  • Messaging: asíncrono, confiable, más complejo

Criterios de decisión

  • Acoplamiento, latencia, formato, confiabilidad, escalabilidad, complejidad, consistencia
  • Justifique el trade-off

REST en 6 reglas

  • Recursos = sustantivos plurales
  • El método da la intención
  • Stateless
  • Códigos de estado con sentido
  • Errores con modelo común
  • Contrato documentado (OpenAPI)

Métodos HTTP

  • GET: seguro, idempotente
  • POST: crea, no idempotente (201)
  • PUT: reemplaza, idempotente
  • PATCH: parcial
  • DELETE: elimina, idempotente (204)

Códigos clave

  • 200, 201, 204
  • 400, 401, 403, 404, 409, 422, 429
  • 500, 502, 503, 504

REST / GraphQL / gRPC / Webhook

  • REST: APIs públicas e interoperabilidad
  • GraphQL: vistas variables, un endpoint
  • gRPC: servicio a servicio, Protobuf, HTTP/2
  • Webhook: notificar eventos a un tercero

OpenAPI

  • openapi, info, servers, paths, components/schemas
  • $ref para reutilizar
  • Ejemplos de request y response

Contract First y taller

  • Necesidad → contrato → validación → implementación
  • Mín.: 3 endpoints, 2 métodos, path y query, body, 2 errores, modelo de error, Postman con 3 requests, README
  • Pesos: 25/20/15/25/15

Error model

  • Mínimo: code, message
  • Bueno: correlationId
  • Nunca siempre 200 ni {"error":true}

Compatibilidad

  • Compatible: agregar campo opcional
  • Incompatible: renombrar o quitar campo
  • Versionar no sustituye diseñar

Caso e-commerce

  • Móvil: GraphQL (o REST + BFF)
  • Inventario: gRPC
  • Pagos externos: REST + webhook

Frase para recordar

  • Problema → interacción → mecanismo → contrato → especificación → implementación
